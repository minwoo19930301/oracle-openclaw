# OCI 에이전트 환경 구축

개인 PC와 독립적으로 실행되는 OpenClaw 환경을 구성한다. 여러 사람이 함께 쓰는 웹앱이 요청되면 별도 서비스로 추가한다. 이것은 구축 방법을 담은 스킬이며 OpenClaw나 Open-Grokbot 런타임 자체를 제공하는 패키지는 아니다.

## 구성과 범위부터 확인

- SSH 별칭 또는 대상 VM, OS/CPU 아키텍처, 기존 서비스, 사용할 모델과 접속 방식을 확인한다. 이미 확인된 설정은 다시 묻지 않는다.
- 기존 VM을 우선 점검한다. 새 VM·유료 모델·계정 권한 확대는 요청 범위를 확인하고, 계정별 자원·비용 한도를 조사한다. 특정 shape를 일률적으로 무료라고 안내하지 않는다.
- OpenClaw만 필요한지, 초대 기반 협업 웹앱·원격 데스크톱까지 필요한지 구분한다. [구성 요소와 경계](references/architecture.md)를 읽고 실제 연결을 설명한다.

## 작업 흐름

1. [구축 절차](references/build-and-verify.md)의 사전 조사로 OS/아키텍처, 서비스 방식, 포트·볼륨·모델 설정의 존재 여부를 확인한다. 비밀값이나 개인 대화를 출력하지 않는다.
2. 설치·업데이트 전 버전과 복원할 상태를 기록한다. 기존 서비스가 있다면 같은 서비스 관리 방식과 상태 경로를 유지한다. 실행 환경을 바꾸려면 별도의 마이그레이션으로 다룬다.
3. OpenClaw는 현재 공식 설치 문서와 설치 버전의 CLI 도움말에 맞춰 구성한다. 이 저장소의 기존 cloud-init/bootstrap 예제를 그대로 실행하지 말고 적용할 설정 차이를 검토한다. 예전 예제의 광범위한 허용 목록·TLS 예외를 새 환경의 기본값으로 옮기지 않는다.
4. 협업 웹앱이 필요하면 방별 인증·권한·저장소와 모델 호출 한도를 구현하고, 앱·공유 데스크톱·HTTPS 프록시를 분리한다. Open-Grokbot을 채택할 경우 제공되는 런타임과 추가로 구현할 웹 계층을 구분한다.
5. 실제 적용할 서비스·환경파일·네트워크 변경을 준비한 뒤, 이미 승인된 범위 안에서 배포한다. 아직 허가되지 않은 외부 변경만 적용 직전에 확인한다.
6. 검증은 **프로세스 상태 → 인증·권한 → 선택한 모델의 실제 응답 → 필요한 채널·도구** 순서로 나눠 기록한다. mock 응답이나 HTTP 200만으로 모델·메신저 왕복·다중 사용자 격리를 확인했다고 보고하지 않는다.
7. 재시작 후 상태 유지, 백업·복원 방법, 현재 릴리스와 남은 설정을 전달한다. 실제 서버를 변경하지 않은 경우 문서/로컬 검증 완료와 운영 배포 완료를 구분한다.

## 운영 중 지킬 경계

- OpenClaw 개인 대화·토큰·작업공간을 협업 웹앱에 자동으로 공유하지 않는다. 두 서비스를 연결하려면 명시적인 인증·사용자/방 매핑과 데이터 범위를 설계한다.
- 공유 데스크톱은 같은 방의 참여자가 같은 화면과 로그인 상태를 본다는 사실을 알린다. 서로 무관한 방은 별도 데스크톱을 사용한다.
- 모델 미연결이면 사람 대화·화면 공유와 봇 기능을 구분해 표시한다. 사진·음성 첨부를 지원한다는 이유로 시각 인식·전사 기능을 주장하지 않는다.
- 실패 시 해당 변경을 멈추고 마지막 정상 설정과 상태 백업으로 복구한다. 상태 DB를 마이그레이션했다면 바이너리만 이전 버전으로 바꾸지 않는다.
