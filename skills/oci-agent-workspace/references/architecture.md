# 구성 요소와 경계

## 서로 다른 세 계층

| 계층 | 역할 | 연결을 확인할 것 |
| --- | --- | --- |
| OpenClaw | 개인 에이전트 Gateway, 모델·메신저·도구 실행 | systemd 또는 컨테이너, 개인 상태 경로, 연결된 모델·채널 |
| 협업 웹앱 | 여러 사용자의 로그인·방·대화·첨부와 봇 실행 요청 | 사용자/방 권한, 세션, 저장소, 전용 모델 설정 |
| 공유 Linux 데스크톱 | 브라우저 화면 공유와 허용된 원격 조작 | 방→컨테이너 매핑, 인증된 WebSocket 프록시, CDP 접근 |

같은 OCI VM에 설치되어 있다는 사실만으로 OpenClaw와 협업 앱의 모델·기억·도구가 연결되지는 않는다. 먼저 실제 adapter나 API 호출 경로를 확인한다. 직접 연결을 원하면 별도 작업으로 구현하고 검증한다.

## Open-Grokbot을 사용할 때

[Open-Grokbot](https://github.com/LING71671/open-grokbot)은 에이전트 실행·메시징 런타임의 참고 구현이다. OpenClaw를 설치하는 프로그램이나 이미 완성된 공개 협업 서비스로 취급하지 않는다.

기준으로 조사한 버전은 `ea516084251a9ff95f32a447e61d2bfa2938a7d4`다. 새 버전을 사용하면 API와 라이선스를 다시 확인한다. GPL-3.0-only 코드·파일을 배포할 때 원본 라이선스·출처를 보존하며, 이 스킬 문서가 upstream의 사용 조건을 바꾸지 않는다.

이 구축 사례에서는 별도 `apps/community` 웹 계층을 추가했다. **해당 디렉터리가 upstream에 포함되어 있다고 가정하지 않는다.** 현재 작업 저장소에 없으면 아래 요구사항에 맞춰 새로 구현하거나, 사용자가 지정한 구현 저장소를 가져온다. 존재하지 않는 `community` 빌드 명령을 실행하지 않는다.

추가 웹 계층의 범위:

- 일회성 사이트 초대, 개인 계정·세션, 방 멤버십과 역할별 권한
- SQLite 기반 계정·방·메시지·첨부 메타데이터와 영속 볼륨
- 사람 메시지와 봇 응답의 방 단위 문맥, 사용자/전체 호출 한도
- 로그인·방 멤버십을 검증하는 noVNC WebSocket 프록시와 짧은 수명의 일회성 티켓
- 방 전용 브라우저 도구와 한 턴의 action/model-call 상한

공개 예시에는 실제 IP, 방 ID, 계정, 세션, 토큰, 대화·첨부 파일을 넣지 않는다. 기능 검증은 합성 데이터와 테스트용 계정으로 진행한다.
